# 中端优化实验报告

日期为 2026-11-09，实验分支为 `experiment/middle-optimizations`，实现基线为提交 `9167ce6`。本报告记录当前阶段的实现与验证结果，并对照课程第 4.2 节列出验收缺口。

## 1. 实验目标

在 LLVM IR 上进行跨基本块常量传播、常量分支裁剪、不可达块删除和死代码消除，同时保持标准输出、返回值、运行时错误及语言定义的其他外部效果。

## 2. 实现方法

语义检查结束后生成 LLVM IR，通过 `-O1` 启用优化，默认 `-O0` 提供对照。当前流水线依次运行 LLVM 的 `mem2reg`、`sccp`、`simplifycfg` 和 `adce`，每次使用 `-verify-each` 检查 IR。

源语言整数算术带有溢出和除零检查，使用运行时辅助调用表示。项目自行实现辅助调用的常量求值，只有操作数已知且计算安全时才替换成常量。随后重新运行流水线，使新常量继续传播，直到没有可折叠的辅助调用。实现位于 `src/ir/optimize.cpp`。

## 3. 优化实例

专项测试使用以下程序，包含常量算术、未使用变量与不可达输出。

```text
def main() -> int {
    var x: int = 2 + 3;
    var unused: int = 7 * 9;
    if (x == 5) { return x * 4; }
    else { print("unreachable"); return 1; }
}
```

优化后 `user_main` 的核心指令为 `ret i64 20`。测试确认函数体中的调用、条件分支、alloca、load 和 store 均已消除，程序退出码为 20，标准输出为空。

## 4. 正确性与副作用

优化前先完成类型检查，因此不可达源分支里的类型错误仍会被拒绝。常量折叠使用有溢出检查的整数运算，遇到除零、溢出或最小整数取负时保留原调用，使诊断继续发生在运行时。

I/O、未知用户调用、数组检查、分配及浮点运行时调用采用保守处理。即使计算结果没有使用，可能产生错误或外部效果的调用仍保留。现有副作用处理依靠 LLVM 对这些调用的保守约定，以及自写折叠器对成功运算的判断。
