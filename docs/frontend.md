# 前端与 AST

## 当前边界

前端使用 C++17、Flex 2.6+、Bison 3.8+。Flex 规则见 [lexer.l](../src/frontend/lexer.l)，完整形式文法见 [parser.y](../src/frontend/parser.y)。CMake 生成 LALR(1) 分析器，并将任何 shift/reduce 或 reduce/reduce 冲突视为构建错误。

前端只负责词法、语法、AST 和源码位置，不执行类型检查或生成 LLVM IR。未定义名称、参数数量、重复声明、非法赋值目标、整数范围、数组元素类型、缺少返回值、并行副作用等由后续 sema 检查。嵌套并行可以在语法树中表示，但应由 sema 按首版范围拒绝。

`.toy` 是示例后缀，命令行不限制扩展名。每个文件是完整的顶层声明序列；不能把一个声明拆成多个文件。多文件解析结果按输入顺序保留，名字解析和入口检查留给后续阶段。空文件在语法上合法。

## 词法规则与位置

| 类别 | 规则 |
| --- | --- |
| 标识符 | `[A-Za-z_][A-Za-z0-9_]*`，区分大小写 |
| 整数字面量 | `[0-9]+`，保留十进制原文；负号是独立的一元运算符 |
| 字符串 | 双引号包围的 ASCII 字节串；控制字符须使用转义 |
| 转义 | `\"`、`\\`、`\n`、`\r`、`\t`、`\0`，以及 `\xHH`（值限于 0–127） |
| 布尔字面量 | `true`、`false` |
| 注释 | `//` 到行末；`/* ... */`，不支持块注释嵌套 |
| 空白 | 空格、制表、换行等，跳过但更新源码位置 |

关键字：`def var struct if elif else while for return parallel map in yield new int bool string void true false`。`range`、`len`、`print` 等是普通标识符，是否为内置函数由语义阶段判断。`let` 不属于声明语法。

Flex 将正规表达式转为自动机：由规则构造 NFA、通过子集构造得到 DFA，生成扫描表；运行时执行最长匹配，长度相同时使用先出现的规则。因此关键字优先于同长标识符，`iffy` 仍是完整标识符，`<=` 不会被拆成两个 token。字符串和块注释分别使用独立词法状态；未知转义、非 ASCII 字符串、非法字节及未闭合字符串/注释均报词法错误。

源码范围使用半开区间 `[begin, end)`。行、列从 1 开始，offset 从 0 开始；列和 offset 按字节计算。CRLF 视为一次换行，同时支持 LF 和 CR。AST、声明名称、参数、字段、并行绑定及 `yield` 均保留位置。

整数字面量先保存为字符串，不在扫描时转为有符号整数，避免丢失 `-9223372036854775808` 的表示能力。越界检查属于 sema；成功导出 AST 不表示这个整数已合法。

## 表层语法

下面是完整 Bison 文法的阅读概览，实际规则以 `parser.y` 为准。所有条件和循环体都必须使用大括号。

```text
文件          := 顶层声明*
顶层声明      := 函数定义 | 结构体定义
函数定义      := def 名称(参数列表?) -> 类型 代码块
参数          := 名称: 类型
结构体定义    := struct 名称 { 字段* } ;?
字段          := 名称: 类型 ;
类型          := 基础类型 | 基础类型[]
基础类型      := int | bool | string | void | 用户类型名称

代码块        := { 语句* }
变量声明      := var 名称: 类型 (= 表达式)? ;
赋值语句      := 表达式 = 表达式 ;
表达式语句    := 表达式 ;
返回语句      := return 表达式? ;
条件语句      := if (表达式) 代码块
                 (elif (表达式) 代码块)* (else 代码块)?
循环          := while (表达式) 代码块
              | for (初始化?; 条件?; 更新?) 代码块
              | for (var 名称: 类型 in 表达式) 代码块
语句          := 上述语句 | 代码块 | ;

数组字面量    := [表达式列表?]
数组创建      := new 基础类型[表达式]
显式转换      := (int | bool | string)(表达式)
并行映射      := parallel map (下标名, 元素名 in 表达式)
                 { 语句* yield 表达式; }
```

数组声明统一采用 `var values: int[] = [1, 2];`。类型语法只接受一维 `T[]`；`new int[n]` 表示数组创建节点，长度在运行时确定。数组和结构体的默认初始化、复制和写入规则尚需语义阶段确定。

函数必须显式写 `-> 返回类型`，无返回值使用 `void`；参数、变量和字段都显式标注类型。`void` 是否处于合法位置由 sema 检查。顶层只接收函数和结构体，`design.md` 中的语句片段需要放入函数体。

结构体使用 `Point(1, 2)` 形式构造，在 AST 中先表示为普通 Call；语义分析根据名称声明区分函数调用与构造。`p.x`、`a[i]` 和调用可以连续组合。表达式列表和参数列表不接受末尾逗号。

C 风格 `for` 的初始化可以是变量声明、赋值或表达式，更新可以是赋值或表达式，三个部分均可省略。范围循环中的 `range(0, n)` 先按普通函数调用表示，迭代范围及类型由 sema 规定。首版未加入 `break`、`continue` 或用户并发原语。

## 优先级与结合性

从高到低：

| 层级 | 构造 | 结合方向 |
| --- | --- | --- |
| 1 | 调用 `f(...)`、索引 `a[i]`、字段 `p.x` | 左 |
| 2 | 一元 `+ - !` | 右 |
| 3 | `* / %` | 左 |
| 4 | `+ -` | 左 |
| 5 | `< <= > >=` | 左 |
| 6 | `== !=` | 左 |
| 7 | `&&` | 左 |
| 8 | `||` | 左 |

优先级由分层文法表达，不依赖生成器默认冲突处理。赋值是语句，不是表达式，不支持 `a = b = 1;`。比较链的类型合法性由 sema 判断。

运算树只表达组合关系，不执行求值；后续代码生成仍必须满足课程要求的从左到右求值和逻辑短路。

## 并行映射的 AST 契约

```text
var output: int[] = parallel map (i, x in input) {
    var value: int = x * x;
    yield value + i;
};
```

`ParallelMapExpr` 包含下标名、元素名、输入表达式、普通语句代码块及独立的结果表达式。末尾 `yield` 被提取为 `result`，并保留 `yield_span`；它不是普通语句，不能出现在其他代码块中。

文法要求恰好一条末尾 `yield`。输入只求值一次、有序结果、空输入、捕获只读、禁止外部写入/输入输出、返回路径和错误行为均需要后续 sema/IR/runtime 实现；当前 AST 不代表这些能力已经完成。

## AST 所有权与接口

- `Program` 持有输入顺序排列的 `SourceFile`；每个文件持有声明。
- 节点按表达式、语句和声明分类，使用 `std::unique_ptr` 形成独占树；析构自动释放子节点。
- `TypeRef` 保留原始类型名及一维数组标记，不把源码类型名提前绑定为具体语义类型。
- 二元表达式、函数实参、数组元素、条件分支和语句列表都保持源码顺序。
- 名字、参数和字段有独立位置，方便 sema 精确诊断。
- 生成的 scanner 是 reentrant，每个 Lexer 持有独立状态；parser 同样是独立实例，不使用共享可变扫描状态。
- 公共解析接口见 [parse.hpp](../src/frontend/parse.hpp)，AST 类型见 [ast.hpp](../src/ast/ast.hpp)。

## 命令行与 JSON

```bash
build/labc --dump-ast examples/frontend/full.toy
build/labc --dump-tokens examples/frontend/full.toy
build/labc --dump-ast --no-locations -o tree.json first.toy second.toy
```

默认模式为 `--dump-ast`，两个模式不能同时选择。`--` 可结束选项解析。AST JSON 包含 `kind`、节点数据及可选 `span`；整数字面量使用字符串 `magnitude`，ASCII NUL 导出为合法 JSON 转义。token JSON 包含类别、字面值（如有）和源码范围，包括 EOF。

任意一个文件发生错误时，不输出部分 JSON。输出文件只在所有文件成功处理后打开；禁止覆盖源文件及其符号链接/硬链接别名。已有输出文件不会在词法/语法失败时被改写。

返回码：成功为 0；词法或语法错误为 1；文件、命令行或内部错误为 2。诊断格式为 `文件:行:列: 类别: 信息`，写入 stderr。
